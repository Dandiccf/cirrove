# Native iCloud package adapter integration

## Contract and current scope

The normal on-demand adapter now considers FILE entries with Pages, Numbers or
Keynote extensions for representation lookup. The extension selects a metadata
request; only an unambiguous, validated Apple `package_token` marks a package.
A Data response leaves the ordinary file unchanged, including a `.pages` file.
No file content is fetched during listing. Up to four metadata lookups run
concurrently; results are cached for 1,024 item/ETag/size identities per provider.
A complete second folder snapshot must match before publishing new classifications.
Unknown native formats and folder-shaped bundles remain outside this classifier;
this is not a general bundle detector or permission to enable account writes.

Confirmed packages are read-only folders, with the same remote item identity and
source logical size retained only for revision checks. Opening one lazily stages
a complete package into an anonymous private account file. Its generated child
uses the actual archive size; its revision includes the original source identity
context and archive SHA-256. The existing streaming hook stages it into the
normal shared cache before directory publication. Native staging currently has
separate storage from the shared block cache: at most two concurrent transfers
and two retained artifacts, each bounded by the account's configured cache size.
In-flight readers can retain references after an artifact leaves this small cache.
This is a per-artifact bound, not an aggregate account-disk-budget guarantee.
Anonymous staging leaves no named artifact to scavenge after a crash.

On an ordinary-cache miss after restart/eviction, the adapter reconstructs source
ID, parent, ETag and logical size from the scoped derived node. It downloads and
verifies the complete package again, then requires the exact old archive identity
and digest. Changed source or generated bytes fail with VersionChanged instead
of serving new bytes under the old revision. Package cache-miss requests have a
bounded 360-second deadline because reconstructing one range may require the
whole archive; other content keeps 30 seconds.

The classifier test fails with package projection removed. It also verifies that
ordinary data with a native extension and similarly named folders are not marked
as packages, listing creates no staging files, repeated stable revisions reuse
lookups and foreign account scopes are refused. Additional fixtures cover
changed-folder classification rejection, cross-block private reads, tampering
and cancellation. The deadline regression is checked before wiring the service
hook. These synthetic checks do not establish real provider support.

The independently maintained [rclone transport source](https://github.com/rclone/rclone/blob/master/backend/iclouddrive/api/drive.go)
was inspected only as protocol evidence: its download lookup also distinguishes
DataToken and PackageToken, while its listed file flags do not supply a package
flag. No rclone dependency, executable, configuration or credentials are used.
The decisive package evidence remains Cirrove's registered live token and range
investigations, not this comparison.

## Registered live arm

Pages sample, serve it through normal Engine/FUSE, survive an offline remount,
and reconstruct that exact published artifact with a fresh provider?
Prediction: all complete SHA-256 reads match the independent source-checked
archive receipt, the published length is the archive length, and no cloud write
occurs. This is one functional arm, not a performance comparison.

Use a fresh UUID and the isolated session from
`21d05f56-70c4-47a8-a5e3-577ab68994ac`. The feature-only command
`--account-package-native SESSION_RUN RUN_UUID` first repeats the independent

Offline provider that refuses content/metadata access; mount and hash again.
Detach. Create another normal adapter with no retained private artifact and
request the published child's staged session directly; read and hash every byte.
This last step exercises provider refetch independent of the first shared cache.

Record command, binary digest, PID, disk-backed TMPDIR and terminal outcome in a
private manifest and public sanitized JSON. Outer timeout 900 seconds; external
reader deadline 180 seconds per mount. No concurrent compilation/measurement.
Keep private source/artifact evidence. No names, document IDs, contents, signed
URLs or credential values in public output. No installed account or daemon change.
The test is read-only on one existing document; it neither extracts nor edits it.

## First arm: failed invariant, retained evidence

Run `2e989d37-ae2d-4982-a3e9-9c34d06570a0` ended with exit 1 after 25.172 seconds.
The normal adapter published a 21,759,419-byte archive under a digest different
from the independent download, despite the same source ETag and length. The
reader rejected that mismatch and the mount detached. Both artifacts were
retained; the normal one was reconstructed from checksum-verified shared-cache
blocks for comparison. Exactly six bytes differed. ZIP entry names/order,
uncompressed lengths and CRCs matched; three empty directory entries had changed
DOS timestamps. No regular file's timestamp changed. This disproves the registered
assumption that two raw package downloads of one source revision are byte-stable.
Public terminal evidence: `icloud-native-package-live-2026-09-30.json`.

## Corrected representation and registered second arm

The normal artifact now uses revision namespace `icloud-artifact-v2` and a ZIP
export with empty-directory DOS timestamps normalized to 1980-01-01. It preserves
regular-file timestamps, names, ordering and compressed payloads. Source receipt
length/SHA-256 is checked before modification; the final canonical digest is
published only after success. A maintained ZIP reader (`zip` 8.6, compression
features disabled) parses metadata; no extraction/decompression/recompression is
performed. Before parser allocation, the classic central directory is bounded
to 10,000 entries and 16 MiB. ZIP64/multidisk, malformed names/offsets, overlapping
entry ranges and nonempty directory payloads are refused. These format/resource
limits and unknown bundle formats remain release limitations.

The timestamp regression fails with normalization disabled and passes when the
patch is applied; it compares whole exports and checks regular-file timestamp
and raw payload preservation. Malformed/truncated archives and mismatched source
receipts return no export. A failed/cancelled normalization may alter private
staging but cannot publish it.

Repeat the same native adapter/mount/offline/refetch arm with a fresh UUID and
binary. Normalize a separate private copy of the independent reference download
using the export contract, leaving the raw receipt artifact untouched. Prediction:
normal mount, offline remount and fresh-provider refetch now produce the exact
canonical reference bytes. Afterward independently compare ZIP entry payloads
between raw and canonical reference with Python (bounded by the known artifact
size); report only booleans/counts, no document names or contents. This verifies
that timestamp normalization is sufficient for this sample, not every iCloud
package generator. Record the second arm separately; do not replace the failure.

The second arm, `3002233f-ed97-4665-9f54-01ea8ed00d2d`, stopped before mounting
(exit 1, 8.670 seconds): canonicalization rejected valid empty Deflate directory
entries. Their uncompressed length/CRC are zero, but their stored Deflate stream
is two bytes; the initial guard incorrectly required zero compressed length.
Evidence: `icloud-native-package-canonical-live-2026-09-30.json`. A synthetic ZIP
with the same empty Deflate representation fails before the fix. The guard now
accepts stored empty entries or the exact empty two-byte Deflate stream, verifies
local/central method and flags, and still refuses encryption/nonempty payloads.

Register a third fresh arm with the same endpoint, reference comparison and
900-second bound. Only the empty-directory ZIP compatibility guard changes;
timestamp normalization and exact canonical byte identity remain mandatory.

## Third arm: passed

Run `16b6673e-f182-489d-8267-f6af26e489f5` passed in 34.204 seconds, including
independent download/reference staging, normal adapter classification, a real
read-only Engine/FUSE read, offline Engine/FUSE remount and a fresh normal-adapter
refetch. All full reads matched the 21,759,419-byte canonical reference; source
logical size was 21,957,877 bytes. Both mounts detached. Evidence:
`icloud-native-package-validated-live-2026-09-30.json`.

Independent Python ZIP validation compared every entry's decompressed SHA-256:
all 56 entries / 53 files (21,957,877 uncompressed bytes) matched between raw and
canonical reference. Entry names/order, methods, CRCs and regular-file timestamps
also matched. No names or contents were emitted. This closes the sampled package
read/refetch gate through the normal adapter, not every native format, ZIP64,
native editing, aggregate staging quota or installed desktop acceptance.

workspace/feature tests, real kernel mounts, scripts, acceptance ledger and docs.
