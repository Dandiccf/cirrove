Privacy policy

This page explains how the Cirrove Linux desktop application accesses, uses, stores and shares Google user data.

1. Scope

This policy covers Cirrove's handling of data through its Google Drive connection. Cirrove is installed and runs on your Linux computer. The source code is public, and the app communicates directly with Google's APIs rather than sending your Drive content through a Cirrove-operated server.

2. Google data Cirrove accesses

After you approve Google sign-in, Cirrove can receive:

  • your Google account identifier, display name, profile image and email address;
  • the names and identifiers of My Drive and Shared Drives available to your account;
  • file and folder metadata in the collection you select, such as names, types, parents, sizes, modification times and provider versions;
  • file content that you open or ask Cirrove to keep offline; and
  • when Allow changes is enabled, ordinary-file content and metadata needed to create, replace, rename, move or trash items.

A read-only connection asks for the Google Drive read-only scope. A connection with Allow changes asks for the full Drive scope because a mounted filesystem must be able to update existing files that were not created by Cirrove. Cirrove presents only the My Drive or Shared Drive you select for that connection.

3. How Cirrove uses Google data

Cirrove uses the data only to provide the filesystem features you choose:

  • identify the connected account and show it in the desktop interface;
  • list the selected drive as folders and files;
  • download file content when you open it or request offline availability;
  • export native Google Docs and Sheets as read-only packages; and
  • send ordinary-file changes back to Google when you explicitly allow changes.

Cirrove does not use Google user data for advertising, sale, credit decisions, or training general-purpose artificial-intelligence or machine-learning models.

4. Local storage and retention

Connection settings, account details, file names and metadata are kept in Cirrove's local state on your computer. Downloaded content is kept in a size-bounded local cache and is evicted as space is needed. Files you choose to keep offline remain pinned until you release the pin or remove the connection. Sign-in credentials are stored in your desktop keyring.

Removing a connection sets its local data aside for recovery for one hour. You can discard that removed data immediately with the command described in the data-removal guide. Uninstalling Cirrove alone does not remove local state or keyring credentials.

5. Sharing and transfers

Cirrove sends requests and user-directed file changes to Google to provide the connected-drive feature. Cirrove does not operate a cloud service that receives your Google Drive files and does not sell them or transfer them to advertising platforms or data brokers. Files exposed through the mounted folder can be opened by applications and users on your computer according to your operating-system permissions.

Cirrove's use of information received from Google Workspace APIs adheres to the Google User Data Policy, including the Limited Use requirements.

6. Security

Cirrove uses encrypted HTTPS connections to Google. OAuth tokens and resumable-upload session credentials are stored in the desktop keyring. Tokens, signed URLs, raw provider responses and file content are not written to Cirrove's service logs.

Local metadata and cached file content are protected by your computer's account and storage security. Cirrove does not add its own encryption layer to those files; use full-disk encryption if your threat model requires encrypted local storage.

7. Your controls

You can make a connection read-only, release offline pins, remove a connection and its local data, delete Cirrove's keyring grant, and revoke Cirrove in your Google Account. The data-removal guide gives the complete sequence. Removing local data does not delete the corresponding files from Google Drive.

8. Changes and contact

This policy will be updated when Cirrove's data handling changes. For privacy questions or requests, contact [CONTACT EMAIL].
